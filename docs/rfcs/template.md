# RFC template

## Summary

Explain the proposed change in a few plain-language sentences.

## Motivation

Describe the concrete problem and who encounters it. Include a small current
example when possible.

## Proposed design

Specify syntax, type rules, runtime behavior, diagnostics, and interactions
with existing features. Show accepted and rejected examples.

## Alternatives

Describe other credible solutions, including keeping the language unchanged.

## Compatibility and migration

State whether existing programs change meaning and how users would update them.

## Implementation and tests

Identify affected compiler stages and the evidence required before the feature
can be documented as implemented.

## Unresolved questions

List decisions reviewers still need to make. An accepted RFC should either
answer them or explicitly defer them.
