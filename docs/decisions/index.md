# Design decisions

A design-decision record explains a choice the project has already made. It
should answer four questions:

1. What problem were we solving?
2. What did we decide?
3. Why did we choose it over the alternatives?
4. What consequences or limitations follow from it?

The language reference remains the place to learn the current rule. Decision
records preserve the reasoning behind rules so future changes do not reopen old
arguments without new evidence. This section is currently scaffolding; existing
decisions still need to be extracted from the README, implementation history,
and documented discussions.

Use the [decision template](template.md) when adding a record.
