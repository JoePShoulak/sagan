# Design-decision template

Copy this page when recording an accepted decision. Replace every prompt and
keep the resulting page marked work-in-progress until it is audited.

## Problem

What user, language, implementation, or compatibility problem required a
decision? Explain unfamiliar terms.

## Decision

State the rule directly. Include the smallest useful Sagan example when the
decision affects source code.

## Why

Explain why this choice fits Sagan's goals. A reader should not need to know
the original conversation to understand the reasoning.

## Alternatives considered

List the serious alternatives and the specific tradeoff that ruled out each
one. Do not invent alternatives merely to make the chosen design look better.

## Consequences

Describe what becomes easier, what becomes harder, and which later decisions
this constrains.

## Evidence

Link the implementation, tests, examples, and reference pages that enforce the
decision.
