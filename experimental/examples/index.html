    Examples

    The root examples/ directory is intentionally small. It contains programs worth reading, changing, and running by hand. Compiler regression inputs live under tests/fixtures/ instead, where their purpose is explicit and the test suite owns them.

    Language showcase

    examples/showcase.sagan is the broad end-to-end tour. It demonstrates Unicode identifiers, collections, control flow, classes and faces, enums, exceptions, dimensioned values, physical units, and native execution.

    fun 🚀(value: Int): Int => value + 2

face Readable {
  fun current(): Int
}

face Countable is Readable {
  fun increment!(): Int
  fun next(): Int => self.current() + 1
}

enum LaunchStatus {
  waiting
  ready
  launched
}

class LaunchCounter is Countable {
  let .value: Int

  new(start: Int) {
    self.value = start
  }

  fun increment!(): Int {
    self.value += 1
    return self.value
  }

  fun .read_value(): Int => self.value

  fun current(): Int => self.read_value()
}

fun finish_early(): Int {
  hope return 42
  finally print("Finally ran before an early return")
}

fun main(): Int {
  let answer = 🚀(40)
  let countdown_start = [3]

  let restored_direction = adjusted_direction - correction

  let halved_direction = doubled_direction / 2.0
  let reversed_direction = -direction
  let maneuver_direction = direction
  maneuver_direction += correction
  maneuver_direction -= correction
  maneuver_direction *= 2.0
  maneuver_direction /= 2.0

  guided_direction.x += 0.5

  print("Face default result: ${next_launch}")
  print("Face dispatch result: ${dispatched_launch}")
  print("Enum status: ${launch_status}")
  print("Exception state: ${exception_state}")
  print("Guarded return: ${guarded_answer}")

  else return 1
}

exit(main())

    Geometry

    examples/geometry.sagan demonstrates the distinction between affine points and displacement vectors, plus native Cartesian and spherical literals.

    fun main(): Int {
  let origin = (10, 20, 30)
  let offset = <1, 2, 3>
  let moved = origin + offset
  let restored = moved - offset
  let travel = moved - origin

  let updated = origin
  updated += offset
  updated -= offset

  let radial_position = s(10.0, 0.5, 1.0)
  let radial_direction = s<2.0, 0.25, 0.75>

  print("Origin: ${origin}")
  print("Moved point: ${moved}")
  print("Restored point: ${restored}")
  print("Travel displacement: ${travel}")
  print("Compound translation restored: ${updated}")
  print("Spherical point: ${radial_position}")
  print("Spherical point radius: ${radial_position.radius}")
  print("Spherical vector: ${radial_direction}")
  print("Spherical vector magnitude: ${radial_direction.magnitude}")

  if moved == (11, 22, 33) and restored == origin and travel == offset and updated == origin and
      radial_position.radius == 10.0 and radial_direction.magnitude == 2.0 return 0
  else return 1
}

exit(main())

    Minimal orbital math

    examples/orbit_math.sagan demonstrates M0's automatically available square root, vector length, squared length, dot product, normalization, and explicit physical-to-display coordinate conversion while preserving native units.

    fun main(): Int {
  let origin = (0.0, 0.0) meter
  let body = (3000.0, 4000.0) meter
  let displacement = body - origin
  let radial_squared = squared_length(displacement)
  let radius = length(displacement)
  let alignment = dot(displacement, <1.0, 0.0> meter)
  let direction = normalized(displacement)
  let display = display_coordinates(body, origin, 1 kilometer)
  let root = sqrt(81.0)

  print("Displacement: ${displacement}")
  print("Squared length: ${radial_squared}")
  print("Length: ${radius}")
  print("Dot with +X: ${alignment}")
  print("Direction: ${direction}")
  print("Display coordinates: ${display}")
  print("Square root: ${root}")

  assert(radial_squared == 25000000.0 meter^2)
  assert(radius == 5000.0 meter)
  assert(alignment == 3000.0 meter^2)
  assert(direction == <0.6, 0.8>)
  assert(display == <3.0, 4.0>)
  assert(root == 9.0)
  return 0
}

exit(main())

/// Updates guidance state from the latest telemetry sample.
fun update_guidance(telemetry_ready: Bool, altitude: Float): GuidanceState {
  telemetry_count += 1
  remaining_fuel -= fuel_burn
  thrust *= throttle
  average_velocity /= sample_count
  ring_index %= ring_capacity
  correction_weight ^= correction_exponent
  if telemetry_ready and altitude >= target_altitude {
    /// Course calculated from the current orbital position.
    let next_course = navigator.current_course(orbital_position, target_position)
    ship.guidance.course = next_course
    ship.guidance.commit!()
  } else if retrying {
    telemetry.retry()
  } else {
    let fallback_course = guidance.safe_course(orbital_position)
    ship.guidance.course = fallback_course
  }
  for sample in trajectory_samples {
    if sample.invalid {
      continue
    }
    while sample.pending {
      sample.refresh!()
      if sample.failed {
        break
      }
    }
  }
  until guidance.converged {
    guidance.refine!(orbital_position, target_position)
  }
  match guidance.status {
    case "ready" {
      telemetry.record(guidance.state)
    }
    case "failed" {
      return
    }
    case else {
      guidance.wait()
    }
  }
  hope {
    telemetry.publish(guidance.state)
  } unless NetworkError {
    telemetry.queue(guidance.state)
  } unless error {
    scream telemetry.wrap(error)
  } finally {
    telemetry.flush!()
  }
  if guidance.failed {
    return
  }
  return guidance.state
}

    The compact Fibonacci example demonstrates parallel let, simultaneous reassignment, postfix increment, and a brace-free one-statement loop. Run it with sagan docs/examples/executable/fibonacci.sagan; its expected output is 144.

    fun fast_fibonacci(n: Int): Int {
  let i, a, b = 0, 0, 1
  while i++ <= n  a, b = b, a + b
  return b
}

print(fast_fibonacci(10))

    Regression fixtures

    tests/fixtures/ is grouped by compiler responsibility:

    • syntax/ contains tokenizer, parser, and recovery inputs.
    • semantic/ contains name, type, ownership, generic, and entry-point inputs.
    • modules/ contains multi-file resolver graphs and failure cases.
    • runtime/ contains code-generation and runtime behavior inputs.

    The scripts in tests/integration/ turn those fixtures into assertions. Run them as part of the complete suite with make test, or separately with:

    make integration-test

    Fixtures are test data, not user-facing examples. A fixture may be deliberately invalid and should not be treated as recommended Sagan style.
